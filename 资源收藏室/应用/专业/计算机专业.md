**知识解答：decimal中的长度与精度分别表示？**
长度：decimal 的长度指的是该数据类型所占用的总位数。长度是通过两个参数来定义的，通常表示为 (M, D)，其中 M 表示总位数，D 表示小数点后的位数。

精度：decimal 的精度指的是小数点后的位数。它表示数值的精确度或小数部分的位数。精度的值不能大于总位数 M，且可以为零。

例如，如果定义一个 decimal(8, 2) 类型的列，则意味着该列可以存储最多 8 位数值，其中小数点后有 2 位。这意味着该列可以表示范围从 -999999.99 到 999999.99 的数值。

### maven仓库中的私库
https://cdn.jsdelivr.net/gh/18476305640/typora@master/images/2025/09/26/1758853103379.png
配置方法：
需要在maven中配置镜像除哪些仓库外（即`repository的id`）不使用这个镜像来拉取，否则私库的依赖也会在setting.xml定义的镜像中拉取，那就拉取不到就报错了。
具体是：

要做的是在maven的setting.xml配置的镜像中进行mirrorOf来排除：
存在问题的：
<mirror>
  <id>huaweicloud</id>
  <mirrorOf>*</mirrorOf> 任何依赖解析时涉及的仓库（central、第三方仓库、私有仓库等），都会被强制重定向到阿里云这个地址!! 不建议这样做
  <url>https://mirrors.huaweicloud.com/repository/maven/</url>
</mirror>

这样修改（注意看右边说明）：
<mirror>
  <id>huaweicloud</id>
  <mirrorOf>*,!com.e-iceblue</mirrorOf>  除了 com.e-iceblue 仓库，其他所有仓库都使用这个镜像。
　　　 <mirrorOf>central</mirrorOf> 只替换中央仓库，其它仓库不受影响（常用在企业环境，避免干扰公司私服）。
  <url>https://mirrors.huaweicloud.com/repository/maven/</url>
</mirror>

com.e-iceblue指的是配置在pom.xml或maven/conf/settings.conf中定义的repository的id：
<repositories>
  <repository>
      <id>com.e-iceblue</id>
      <name>e-iceblue</name>
      <url>https://repo.e-iceblue.cn/repository/maven-public/</url>
  </repository>
</repositories>

### 创建并启动容器
```bash
docker run 参数 版本:版本号 </bin/bash>   # 默认为/bin/bash
```
- **参数说明**：
    - `-i`：保持容器运行。通常与`-t`同时使用。加入`it`这两个参数后，容器创建后自动进入容器中，退出容器后，容器自动关闭。
    - `-t`：为容器重新分配一个伪输入终端，通常与`-i`同时使用。
    - `-d`：以守护（后台）模式运行容器。创建一个容器在后台运行，需要使用`docker exec`进入容器，示例：`docker exec -it c2 /bin/bash`。退出后，容器不会关闭。
    - `-it`：创建的容器一般称为交互式容器。
    - `-id`：创建的容器一般称为守护式容器。
    - `--name`：为创建的容器命名。
    - `-p`：`-p <宿主机端口>:<docker容器虚拟机端口>`。

> - `-it` 启动交互式容器
> - `-d` 启动守护式容器。如果容器中的应用应该以守护的方式运行，那就会导致容器的自杀，因为容器觉得当前已经没有什么事情可做了。此时需要结合 `-it -d`，`-it` 让程序觉得还有事，`-d` 表示在后台运行（或进入容器终端后，使用 `Ctrl+P+Q` 也可以退出且保持在后台运行）。

### 进入容器

- **exec 方式**：进入容器后，使用 `exit` 退出后容器不会停止。
  ```bash
  docker exec 参数      # 退出容器，容器不会关闭
  # 示例：docker exec -it c_mysql /bin/bash
  ```

- **attach 方式**：与 `exec` 不同，进入容器后，使用 `exit` 退出后容器会停止。使用 `Ctrl+P+Q` 退出交互模式并保持容器运行。
  ```bash
  docker attach 容器ID
  ```

#强制删除：docker rm -f 容器名称或ID

### 导入导出命令
导出命令不会保留容器状态，容器中之前运行创建的文件会一同导出为镜像文件。导入后，重新运行容器时，之前里面的服务不会自动启动（例如 tomcat）。

## 2、使用telepresence

`telepresence helm install`， 会向k8s中安装`traffic-manager`, 安装在命名空间 `ambassador`下.

在IDEA安装`kubernetes`插件，进行下面的配置，如果用到telepresence也会识别本地是否安装telepresence。
![](https://cdn.jsdelivr.net/gh/18476305640/typora@master/images/2025/07/15/1752561797193.png)

先让telepresence connect：
![](https://cdn.jsdelivr.net/gh/18476305640/typora@master/images/2025/07/15/1752563299996.png)
然后就可以拦截depoloy的指定端口了,填入`localPort:remotePort/name` 与telepresence intercept支持的参数：
![](https://cdn.jsdelivr.net/gh/18476305640/typora@master/images/2025/07/15/1752563367683.png)

> 如果匹配端口有两个service，那可能还要指定要拦截哪个service了。
> `telepresence intercept my-deployment --port 8080:http --service my-service-a`

注意：`telepresence intercept my-deployment --port 8080:http` 8080是本地要对接的服务，而http是拦截的端口的名称，为什么不直接写端口，这是因为如果你k8s如果版本小于`1.29`版本，此时pod中没有iptable，使用http这种的话就可以避免 Telepresence 注入init-container来插入iptables规则。不知道是否有说错，可以[具体参考官网](https://telepresence.io/docs/troubleshooting#injected-init-container-doesnt-function-properly) 。所以如果不这样做可能就无法拦截，拦截时命令执行失败！
```yml
apiVersion: v1
kind: Pod
metadata:
  ...
spec:
  containers:
    - ports:
      - name: http
        containerPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  ...
spec:
  ports:
    - port: 80
      targetPort: http
```


telepresence主要是拦截指定namespace->deploy->容器 的端口的请求拦截转发到本地服务下，配置继续看下面
如果是微服务，在暴露服务地址时，也要配置，以nacos为例：
```yml
spring:
  cloud:
    nacos:
      discovery:
        # 开发环境需要（生产也可用），不直接调用pod，而是交给k8s service进行请求路由
        ip: spark-coupon.spark-test.svc.cluster.local
```
> 如果不配置上面，由于微服务注册的地址是pod的地址，而telepresence又拦截不了pod的地址，所以要配置，如果后面可以了，猜测可能跟k8s集群版本与telepresence都要支持有关。
